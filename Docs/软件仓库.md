## 核心应用

### sle_measure_dis（单链路测距）

Server/Client 模式，使用 SLE Channel Sounding IQ 测量两点距离。

测距链路：

1. SLE 建链后启用 Channel Sounding
2. CS 回调输出本端 IQ 报告，按 timestamp_sn 与 report_idx 聚合完整 IQ 帧
3. 一端通过 SSAP 把本端 IQ 传给另一端
4. 测距端检查本地/远端 IQ 时间戳匹配
5. 调用 `slem_alg_calc_smoothed_dis()` 计算距离
6. 应用层线性校正：`corrected = 0.7079 * measured - 0.1938`

关键参数：

- `TOF_DEFAULT = 2070`
- `DIS_ALG_MODE = 6`（V3 测距算法变体）
- `DIS_ALG_CALIB_VAL = 0.0f`

关键文件：

- `sle_measure_dis_server/sle_measure_dis_server_alg.c`
- `sle_measure_dis_client/`

### sle_locate（多基站定位）

1 Tag + 最多 4 Anchor 的星闪定位系统。

角色划分：

- **Anchor：** 固定基站，SSAP Server 广播。接收 Tag IQ，结合本地 IQ 计算距离，通知 Tag。
- **Tag：** 移动标签，SSAP Client 扫描连接多个 Anchor。维护连接、属性句柄和 IQ 缓冲。收到各 Anchor 距离后执行定位解算。

定位算法：

- 以 ANC0 为参考，消去非线性项，构建线性方程组 `A * p = b`
- 最小二乘解：正规方程 `(A^T A) p = A^T b`
- 2D 模式：2x2 Cramer 法则
- 3D 模式：3x3 Gauss-Jordan 消元
- 输出残差 RMS 作为质量指标

GTTT 调度：

- `enlarge_ratio = Anchor 数量`
- `sched_order = Anchor 槽位`
- 槽位绑定 MAC 表，断连重建不扰乱其他链路

默认 Anchor 几何（Kconfig 配置）：

| Anchor |  X/mm | Y/mm | Z/mm | MAC 末字节 |
| ------ | ----: | ---: | ---: | ---------- |
| ANC0   |     0 |    0 | 2558 | 0x01       |
| ANC1   |  4000 |    0 | 2665 | 0x02       |
| ANC2   | -2310 | 5040 | 2686 | 0x03       |
| ANC3   |  1050 | 4000 | 1250 | 0x04       |

关键文件：

- `common/sle_locate_common.h`：公共 UUID、消息格式
- `anchor/sle_locate_anchor.c`：Anchor 广播和连接管理
- `anchor/sle_locate_anchor_alg.c`：Anchor 端测距算法
- `tag/sle_locate_tag.c`：Tag 扫描连接和调度
- `tag/sle_locate_trilateration.c`：2D/3D 定位求解器
- `Kconfig`：角色、MAC、Anchor 数量和坐标配置

## 构建方式

### 前置条件

- uv
- Python 3.8+（由 uv 创建和管理虚拟环境）
- FBB BS2X SDK 完整源码
- CMake 构建工具链
- 目标平台：`standard-bs21e-1100e`

`build.py` 不在 `sle_local/` 根目录，而在 `sle_local/src/build.py`。仓库根目录提供
`pyproject.toml` 和 `uv.lock`，首次构建先同步 Python 依赖：

```bash
cd sle_local
UV_CACHE_DIR=.uv-cache uv sync
```

### 单次全量编译

```bash
cd sle_local

# 全量编译（-c 参数清除缓存重新构建，-ninja 使用 Ninja）
UV_CACHE_DIR=.uv-cache CCACHE_DIR=.ccache \
  uv run --directory src python build.py -c -ninja standard-bs21e-1100e

# 增量编译（修改代码后快速重编）
UV_CACHE_DIR=.uv-cache CCACHE_DIR=.ccache \
  uv run --directory src python build.py -ninja standard-bs21e-1100e
```

### Kconfig 图形配置

```bash
cd sle_local
UV_CACHE_DIR=.uv-cache CCACHE_DIR=.ccache \
  uv run --directory src python build.py -c standard-bs21e-1100e menuconfig
```

在 Kconfig 菜单中配置角色和外设：

| 菜单路径                                                    | 配置项                     | Tag 推荐值 | 说明         |
| ----------------------------------------------------------- | -------------------------- | ---------- | ------------ |
| `Application → samples → products → Select SLE locate role` | `Tag (client)`             | `y`        | 选 Tag 角色  |
| `Peripheral configuration`                                  | `SLE_LOCATE_ENABLE_ADC`    | `y`        | 电池电压监测 |
| `Peripheral configuration`                                  | `SLE_LOCATE_ENABLE_PWM`    | `y`        | 蜂鸣器驱动   |
| `Peripheral configuration`                                  | `SLE_LOCATE_ENABLE_NFC`    | `n`        | 当前仅 NDEF/接口框架，HAL 调用尚未接通 |
| `Peripheral configuration`                                  | `SLE_LOCATE_ENABLE_I2C`    | `y`        | LIS2DW12 总线；仍需增加传感器业务驱动 |
| `Peripheral configuration`                                  | `SLE_LOCATE_ENABLE_BUTTON` | `n`        | 当前无专用按键，默认 GPIO_25 与 SWDCLK 冲突 |
| `Peripheral configuration`                                  | `SLE_LOCATE_ENABLE_PM`     | `n`        | 当前 LIGHT/DEEP 主要退化为 `osal_msleep` |

操作说明：

- 空格/回车：选中或反选配置项
- `S`：保存配置
- `Q` 或 `ESC`：退出

Anchor 固件配置类似，只需将角色选为 `Anchor` 并设置 Anchor 序号和 MAC。

### 批量构建（Tag + 多 Anchor）

```bash
cd sle_local
# 构建 4 个 Anchor + 1 个 Tag 的全部固件
UV_CACHE_DIR=.uv-cache CCACHE_DIR=.ccache \
  uv run python tools/build_locate_firmwares.py --num-anchors 4

# 仅构建部分角色
UV_CACHE_DIR=.uv-cache CCACHE_DIR=.ccache \
  uv run python tools/build_locate_firmwares.py --only tag anchor0 anchor1
```

编译产物路径：

```
src/output/bs21e/fwpkg/standard-bs21e-1100e/bs21e_all_in_one.fwpkg
```

批量构建后产物归档到：

```
output/firmware/locate/<role>/
```

## 烧录方式

### 前置准备

| 项目         | 要求                                                                                 |
| ------------ | ------------------------------------------------------------------------------------ |
| 硬件焊接状态 | U1(BS21E)、晶振 X1+C9、L1(2.2uH)、去耦电容、R11/R12(UART 电阻)、R1/R2(SWD 电阻)      |
| 供电         | CR2032 电池，确认 TP7(SLE_3V3) = 3.0V~3.2V                                           |
| 最小系统自检 | DEC4 对 GND 应测得 1.2V~1.8V (BUCK 输出)；32MHz 晶振起振；SWD 可识别芯片             |
| 烧录工具     | 本地源码 `hisiflash/`，BS2X/BS21E 使用实验性 SEBOOT/YMODEM 串口烧录支持              |
| 串口         | USB-to-TTL 连接 TX、RX、GND；当前板卡使用 CH340/CH341，Linux 下通常为 `/dev/ttyUSB0` |
| 固件         | `sle_local/src/output/bs21e/fwpkg/standard-bs21e-1100e/bs21e_all_in_one.fwpkg`       |

### 构建 hisiflash

源码已位于项目根目录的 `hisiflash/`。首次使用或源码更新后编译 release 版本：

```bash
cd hisiflash
cargo build --release
./target/release/hisiflash --version
```

也可安装到 `~/.cargo/bin/hisiflash`：

```bash
cd hisiflash
cargo install --path hisiflash-cli
```

以下命令使用本地源码构建出的 `hisiflash/target/release/hisiflash`，避免系统安装版与源码版本不一致。

### 检查串口和固件

```bash
cd /home/otto/桌面/Project/嵌入式/嵌赛

# 应自动识别 CH340/CH341 串口，例如 /dev/ttyUSB0
./hisiflash/target/release/hisiflash list-ports

  sle_local/src/output/bs21e/fwpkg/standard-bs21e-1100e/bs21e_all_in_one.fwpkg
```

### 烧录步骤

1. 连接 USB-to-TTL 的 TX、RX、GND，并给板卡供电。
2. 执行烧录命令。BS21E 必须明确指定 `-c bs2x`；CH340/CH341 推荐使用 `460800` 烧录波特率：

```bash
cd /home/otto/桌面/Project/嵌入式/嵌赛

./hisiflash/target/release/hisiflash \
  -c bs2x -p /dev/ttyUSB0 -b 460800 \
  flash sle_local/src/output/bs21e/fwpkg/standard-bs21e-1100e/bs21e_all_in_one.fwpkg
```

3. 出现“等待设备...（复位以进入下载模式）”后，按下并释放板卡 **RST**，或重新上电。
4. 等待全部 FWPKG 分区写入、校验并复位。命令退出码为 `0` 表示烧录成功。

如串口已能被唯一识别，可省略 `-p /dev/ttyUSB0`。如使用批量构建的固件，将最后一个参数替换为
`sle_local/output/firmware/locate/<role>/bs21e_all_in_one.fwpkg`。

### 烧录批量构建的固件

``bash
PORT=$(hisiflash list-ports 2>/dev/null | grep -o '/dev/ttyUSB[0-9]*' | head -1)

# Tag

### 验证烧录结果

推荐烧录成功后直接进入 `115200` 串口监控，避免重新打开串口时丢失早期启动日志：

```bash
  PORT=$(hisiflash list-ports 2>/dev/null | grep -o '/dev/ttyUSB[0-9]*' | head -1)
  hisiflash \
    -c bs2x -p ${PORT:-/dev/ttyUSB0} -b 460800 \
    flash src/output/bs21e/fwpkg/standard-bs21e-1100e/bs21e_all_in_one.fwpkg \
    --monitor --monitor-baud 115200
```

只查看串口日志：

```bash
PORT=$(hisiflash list-ports 2>/dev/null | grep -o '/dev/ttyUSB[0-9]*' | head -1)
./hisiflash/target/release/hisiflash -p ${PORT:-/dev/ttyUSB0} \
  monitor --monitor-baud 115200
```

板卡上电或按 RST 后，串口应输出启动日志：

```text
[TAG] SLE enable status=0x0
[TAG] locate_tag_init complete — scanning for 8 anchors
[ADC] initialized on AIN0, divider=3.0
[BUZZER] initialized on GPIO_6
[TAG] boot: battery 3012 mV (100%)
```

`Ctrl+C` 退出监控，`Ctrl+R` 尝试通过 DTR/RTS 复位，`Ctrl+T` 切换时间戳。蜂鸣器上电自检和
ADC 日志仅在对应 Kconfig 功能已启用时出现。

### 常见问题

| 现象                               | 可能原因                          | 排查方法                                                             |
| ---------------------------------- | --------------------------------- | -------------------------------------------------------------------- |
| `list-ports` 未显示 `/dev/ttyUSB0` | USB-to-TTL 未识别、线缆或驱动问题 | 重新插拔并检查 `dmesg`；确认 CH340/CH341 被系统识别                  |
| `Permission denied`                | 当前用户无串口权限                | 将用户加入 `dialout` 组后重新登录，或检查 `/dev/ttyUSB0` 权限        |
| 等待设备时按 RST 无反应            | TX/RX 线路不通、线序反接或未共地  | 检查 R11/R12、TX/RX 交叉连接和 GND；确认 UART 烧录引脚复用正确       |
| 烧录传输失败/超时                  | 波特率过高或芯片未正常工作        | 使用 BS2X 推荐的 `460800`；确认 TP7≈3V、DEC4≈1.2-1.8V，检查晶振      |
| FWPKG 解析或 CRC 失败              | 产物不完整或选错文件              | 先执行 `hisiflash -c bs2x info <fwpkg>`，应显示 `CRC Valid: Yes`     |
| 烧录成功但串口无日志               | UART 参数错误或引脚复用           | 确认波特率 115200，TX/RX 线序正确，SLE_3V3 供电正常                  |
| 烧录后蜂鸣器不响                   | 硬件未焊接驱动电路                | 确认 R9(1k)/R16(10k)/Q3(S8050)/BUZZER2 已焊接，Kconfig 中 PWM 已开启 |

注意：烧录前必须确认最小系统供电正常。如果 DEC4 电压为 0V 或等于 VBAT，说明 BUCK 未工作。此时优先检查 **L1 是否为 2.2uH 功率电感**（不是磁珠，不是 0R 电阻），以及 DCC/DEC4 的焊接质量。

## 实验数据

数据源：`output/measurements_v3_v4.csv`

- 样本数：90,526
- 距离点：0.5m / 1.0m / 1.5m / 2.0m / 2.5m / 3.0m / 3.5m
- 会话数：8
- 算法：V3，DIS_ALG_MODE = 6

关键结论：

- V3 原始距离在所有测试点存在系统性高估（Bias +0.2m ~ +1.7m）
- 线性校正可压低偏差但非根本解决，需标定 TOF_DEFAULT 和每 Anchor bias
- 1.5m 和 3.5m 存在相位解模糊双峰问题

### 2026-06-12 源码实现审查

| 功能 | 审查结论 | 交付前动作 |
| --- | --- | --- |
| ADC | 有实际 ADC 初始化和读取路径 | 上板校准分压与电量曲线 |
| 蜂鸣器 PWM | 有实际 PWM 初始化和鸣叫路径 | 上板验证声压、峰值电流和复位风险 |
| I2C | 有 HAL 时执行实际读写；无 HAL 时返回失败 | 增加 LIS2DW12 初始化、WHO_AM_I 和运动事件处理 |
| NFC | HAL 初始化、NDEF 装载、场检测和 Tag 启动调用均被注释 | 对接当前 SDK NFC API 后再启用 |
| 按钮 | 当前 PCB 无专用按键；默认 GPIO_25 与 SWDCLK 冲突；分类器不会产生双击事件 | 重新分配硬件引脚并完成双击状态机 |
| PM | LIGHT/DEEP 的真实 LiteOS/PMU 调用被注释，主要执行 `osal_msleep` | 对接 SDK PM、唤醒源和外设挂起恢复 |
| 调试 LED | 原理图已有 GPIO_03/04/05 LED，源码没有驱动 | 增加板级定义、Kconfig 与状态策略 |

当前活动 `standard_bs21e_1100e.config` 中 ADC/PWM/NFC/I2C/BUTTON/PM 六个外设开关均为 `n`。在上述阻塞项处理前，Tag 建议从以下最小配置开始：

```
CONFIG_SLE_LOCATE_ENABLE_ADC=y
CONFIG_SLE_LOCATE_ENABLE_PWM=y
CONFIG_SLE_LOCATE_ENABLE_I2C=y
# CONFIG_SLE_LOCATE_ENABLE_NFC is not set
# CONFIG_SLE_LOCATE_ENABLE_BUTTON is not set
# CONFIG_SLE_LOCATE_ENABLE_PM is not set
```
