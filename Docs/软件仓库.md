## 核心应用

### sle_measure_dis（单链路测距）

Server/Client 模式，使用 SLE Channel Sounding IQ 测量两点距离。

测距链路：
1. SLE 建链后启用 Channel Sounding
2. CS 回调输出本端 IQ 报告，按 timestamp_sn 与 report_idx 聚合完整 IQ 帧
3. 一端通过 SSAP 把本端 IQ 传给另一端
4. 测距端检查本地/远端 IQ 时间戳匹配
5. 调用 `slem_alg_calc_smoothed_dis()` 计算距离
6. 应用层线性校正：`corrected = 0.7079 * measured - 0.1938`

关键参数：
- `TOF_DEFAULT = 2070`
- `DIS_ALG_MODE = 6`（V3 测距算法变体）
- `DIS_ALG_CALIB_VAL = 0.0f`

关键文件：
- `sle_measure_dis_server/sle_measure_dis_server_alg.c`
- `sle_measure_dis_client/`

### sle_locate（多基站定位）

1 Tag + 最多 4 Anchor 的星闪定位系统。

角色划分：
- **Anchor：** 固定基站，SSAP Server 广播。接收 Tag IQ，结合本地 IQ 计算距离，通知 Tag。
- **Tag：** 移动标签，SSAP Client 扫描连接多个 Anchor。维护连接、属性句柄和 IQ 缓冲。收到各 Anchor 距离后执行定位解算。

定位算法：
- 以 ANC0 为参考，消去非线性项，构建线性方程组 `A * p = b`
- 最小二乘解：正规方程 `(A^T A) p = A^T b`
- 2D 模式：2x2 Cramer 法则
- 3D 模式：3x3 Gauss-Jordan 消元
- 输出残差 RMS 作为质量指标

GTTT 调度：
- `enlarge_ratio = Anchor 数量`
- `sched_order = Anchor 槽位`
- 槽位绑定 MAC 表，断连重建不扰乱其他链路

默认 Anchor 几何（Kconfig 配置）：

| Anchor | X/mm | Y/mm | Z/mm | MAC 末字节 |
| --- | ---: | ---: | ---: | --- |
| ANC0 | 0 | 0 | 2558 | 0x01 |
| ANC1 | 4000 | 0 | 2665 | 0x02 |
| ANC2 | -2310 | 5040 | 2686 | 0x03 |
| ANC3 | 1050 | 4000 | 1250 | 0x04 |

关键文件：
- `common/sle_locate_common.h`：公共 UUID、消息格式
- `anchor/sle_locate_anchor.c`：Anchor 广播和连接管理
- `anchor/sle_locate_anchor_alg.c`：Anchor 端测距算法
- `tag/sle_locate_tag.c`：Tag 扫描连接和调度
- `tag/sle_locate_trilateration.c`：2D/3D 定位求解器
- `Kconfig`：角色、MAC、Anchor 数量和坐标配置

## 构建方式

### 前置条件

- Python 3.8+
- FBB BS2X SDK 完整源码
- CMake 构建工具链
- 目标平台：`standard-bs21e-1100e`

### 单次全量编译

```bash
cd sle_local/src

# 全量编译（-c 参数清除缓存重新构建）
python3 build.py -c standard-bs21e-1100e

# 增量编译（修改代码后快速重编）
python3 build.py standard-bs21e-1100e
```

### Kconfig 图形配置

```bash
python3 build.py -c standard-bs21e-1100e menuconfig
```

在 Kconfig 菜单中配置角色和外设：

| 菜单路径 | 配置项 | Tag 推荐值 | 说明 |
| --- | --- | --- | --- |
| `Application → samples → products → Select SLE locate role` | `Tag (client)` | `y` | 选 Tag 角色 |
| `Peripheral configuration` | `SLE_LOCATE_ENABLE_ADC` | `y` | 电池电压监测 |
| `Peripheral configuration` | `SLE_LOCATE_ENABLE_PWM` | `y` | 蜂鸣器驱动 |
| `Peripheral configuration` | `SLE_LOCATE_ENABLE_NFC` | `y` | NFC Tag 模拟 |
| `Peripheral configuration` | `SLE_LOCATE_ENABLE_I2C` | 按需 | 外部传感器 |
| `Peripheral configuration` | `SLE_LOCATE_ENABLE_BUTTON` | `y` | 按键输入 |
| `Peripheral configuration` | `SLE_LOCATE_ENABLE_PM` | `y` | 低功耗管理 |

操作说明：
- 空格/回车：选中或反选配置项
- `S`：保存配置
- `Q` 或 `ESC`：退出

Anchor 固件配置类似，只需将角色选为 `Anchor` 并设置 Anchor 序号和 MAC。

### 批量构建（Tag + 多 Anchor）

```bash
cd sle_local
# 构建 4 个 Anchor + 1 个 Tag 的全部固件
python3 tools/build_locate_firmwares.py --num-anchors 4

# 仅构建部分角色
python3 tools/build_locate_firmwares.py --only tag anchor0 anchor1
```

编译产物路径：
```
src/output/bs21e/fwpkg/standard-bs21e-1100e/bs21e_all_in_one.fwpkg
```

批量构建后产物归档到：
```
output/firmware/locate/<role>/
```

## 烧录方式

### 前置准备

| 项目 | 要求 |
| --- | --- |
| 硬件焊接状态 | U1(BS21E)、晶振 X1+C9、L1(2.2uH)、去耦电容、R11/R12(UART 电阻)、R1/R2(SWD 电阻) |
| 供电 | CR2032 电池，确认 TP7(SLE_3V3) = 3.0V~3.2V |
| 最小系统自检 | DEC4 对 GND 应测得 1.2V~1.8V (BUCK 输出)；32MHz 晶振起振；SWD 可识别芯片 |
| 驱动 | [CH341SER 驱动](https://www.wch.cn/downloads/CH341SER_EXE.html) 已安装 |
| 线缆 | Type-C 数据线连接板卡与 PC |

### 烧录步骤

1. **连接硬件**
   - Type-C 线一头接 PC，一头接板卡 USB 接口
   - 板载 USB-to-TTL 芯片自动连接 TX(UART_TXD)、RX(UART_RXD)、GND 测试点

2. **打开 BurnTool**
   - 下载 [BurnTool](https://gitee.com/hihope_iot/near-link/tree/master/tools)
   - 启动 `BurnTool.exe`
   - 点击菜单 `Option` → 选择芯片型号：**WS63**（BS21E 与 WS63 同系列）

3. **选择串口**
   - 在 BurnTool 主界面下拉选择 CH341SER 对应的 COM 端口号

4. **选择烧录文件**
   - 点击 `Browse`，选择编译产物：
   ```
   sle_local/src/output/bs21e/fwpkg/standard-bs21e-1100e/bs21e_all_in_one.fwpkg
   ```
   - 如使用预编译固件，选择 `output/firmware/locate/<role>/bs21e_all_in_one.fwpkg`

5. **烧录参数设置**
   - 勾选 `Auto Burn`（自动检测芯片上电后开始烧录）
   - 勾选 `Auto Disconnect`（烧录完成后自动断开连接）
   - 点击 `Connect` 按钮

6. **触发烧录**
   - 按下板卡上的 **RST 按键**（或短接 NRST 测试点到 GND 后释放）
   - BurnTool 检测到芯片复位信号后自动启动烧录
   - 等待进度条走完，提示 `Burn Success`
   - 烧录成功后可断开连接

### 验证烧录结果

1. 打开串口工具（sscom / XShell），选择同一 COM 端口
2. 波特率设为 **115200**
3. 板卡上电或按 RST，串口应输出启动日志：

```text
[TAG] SLE enable status=0x0
[TAG] locate_tag_init complete — scanning for 4 anchors
[ADC] initialized on AIN0, divider=3.0
[BUZZER] initialized on GPIO_6
[TAG] boot: battery 3012 mV (100%)
```

4. 蜂鸣器上电时应发出一声短鸣（100ms 自检）

### 常见问题

| 现象 | 可能原因 | 排查方法 |
| --- | --- | --- |
| BurnTool 未检测到串口 | CH341SER 驱动未安装或安装失败 | 重新安装驱动，确认设备管理器显示 COM 端口；如显示"驱动预安装成功"表示失败 |
| 点击 Connect 后按 RST 无反应 | TX/RX 线路不通 | 检查 R11/R12 是否焊接，Type-C 线是否数据线，尝试换线 |
| 烧录失败/超时 | 芯片未正常工作 | 确认最小系统供电（TP7≈3V，DEC4≈1.2-1.8V），晶振是否起振 |
| 烧录成功但串口无日志 | UART 参数错误或引脚复用 | 确认波特率 115200，TX/RX 线序正确，SLE_3V3 供电正常 |
| 烧录后蜂鸣器不响 | 硬件未焊接驱动电路 | 确认 R9(1k)/R16(10k)/Q3(S8050)/BUZZER2 已焊接，Kconfig 中 PWM 已开启 |

注意：烧录前必须确认最小系统供电正常。如果 DEC4 电压为 0V 或等于 VBAT，说明 BUCK 未工作。此时优先检查 **L1 是否为 2.2uH 功率电感**（不是磁珠，不是 0R 电阻），以及 DCC/DEC4 的焊接质量。

## 实验数据

数据源：`output/measurements_v3_v4.csv`
- 样本数：90,526
- 距离点：0.5m / 1.0m / 1.5m / 2.0m / 2.5m / 3.0m / 3.5m
- 会话数：8
- 算法：V3，DIS_ALG_MODE = 6

关键结论：
- V3 原始距离在所有测试点存在系统性高估（Bias +0.2m ~ +1.7m）
- 线性校正可压低偏差但非根本解决，需标定 TOF_DEFAULT 和每 Anchor bias
- 1.5m 和 3.5m 存在相位解模糊双峰问题

## 外设驱动模块 (`peripheral/`)

`v0.2.0` 新增完整的外设驱动框架，所有模块通过 Kconfig 开关条件编译：

| 模块 | 文件 | Kconfig | GPIO | 功能 |
| --- | --- | --- | --- | --- |
| 电池 ADC | `sle_locate_adc.c/h` | `SLE_LOCATE_ENABLE_ADC` | GPIO_02/AIN0 | CR2032 电压采集与电量估算 |
| 蜂鸣片 PWM | `sle_locate_buzzer.c/h` | `SLE_LOCATE_ENABLE_PWM` | GPIO_06 | 4kHz PWM 驱动，开/关/定时鸣叫 |
| NFC Tag | `sle_locate_nfc.c/h` | `SLE_LOCATE_ENABLE_NFC` | NFC1/NFC2 | NFC-A Tag 模拟，NDEF 配置，场检测 |
| I2C | `sle_locate_i2c.c/h` | `SLE_LOCATE_ENABLE_I2C` | GPIO_14/SCL, GPIO_15/SDA | 100kHz 主机，寄存器读写，总线扫描 |
| 按键 | `sle_locate_button.c/h` | `SLE_LOCATE_ENABLE_BUTTON` | GPIO_25 | 短按/长按/双击，去抖动，ISR 回调 |
| 功耗管理 | `sle_locate_pm.c/h` | `SLE_LOCATE_ENABLE_PM` | — | IDLE/LIGHT/DEEP 睡眠，电量缓存，空闲超时 |
| 板级定义 | `sle_locate_board.h` | 始终包含 | 全部 | 引脚映射、ADC 分压比、PWM 频率 |

Tag 固件推荐 Kconfig 配置：
```
CONFIG_SLE_LOCATE_ENABLE_ADC=y
CONFIG_SLE_LOCATE_ENABLE_PWM=y
CONFIG_SLE_LOCATE_ENABLE_NFC=y
CONFIG_SLE_LOCATE_ENABLE_BUTTON=y
CONFIG_SLE_LOCATE_ENABLE_PM=y
```
