# 测试方案

## 测试目标

验证 BS21 室内协同定位系统在单链路测距和多基站定位两个场景下的功能完整性和精度表现。

## 前置条件

- 硬件：BS21 实物板卡（含蜂鸣片、NFC 线圈）
- 烧录环境：本地 `hisiflash` + USB-to-TTL 转 TX/RX/GND，BS2X 烧录波特率 460800
- 调试环境：串口工具（sscom/xshell），115200 baud
- 软件：`sle_local/` 仓库，预编译固件位于 `output/firmware/locate/`

> 注意：阶段四外设功能验证中的 NFC 测试和蜂鸣器测试，取决于以下硬件问题是否已修复：
> - NFC 线圈符号已从电阻占位替换为实际线圈封装并启用转 PCB
> - BUZZER2 已替换为实际蜂鸣片封装并启用转 PCB
> - 原理图 DRC 已通过
> 在上述问题修复前，外设测试暂不可执行。

> 软件实现边界：NFC HAL 和真实 LIGHT/DEEP 睡眠调用当前仍是占位；按钮默认 GPIO_25 与 SWDCLK 冲突，且双击分类尚未实现；GPIO_03/04/05 调试 LED 尚无固件驱动。对应测试必须在源码阻塞项处理后执行。

## 阶段一：单板功能验证

**目标：** 确认单板能正常启动、SLE 广播正常发出。

| 步骤 | 操作 | 预期结果 |
| --- | --- | --- |
| 1 | 使用 `hisiflash -c bs2x ... flash ... --monitor --monitor-baud 115200` 烧录 `tag` 固件 | hisiflash 提示烧录成功并进入监控 |
| 2 | 上电或复位，串口 115200 查看输出 | 启动日志正常，无 exception/assert |
| 3 | 查看 SLE 初始化日志 | SLE 协议栈初始化成功 |
| 4 | Tag 开始扫描广播 | 串口输出扫描到的 Anchor 列表 |

## 阶段二：单链路测距

**目标：** 验证 CS 测距链路和 V3 算法精度。

| 步骤 | 操作 | 预期结果 |
| --- | --- | --- |
| 1 | 2 块板分别烧录 server/client (sle_measure_dis) | 烧录成功 |
| 2 | 两板间距 1m，上电 | 建链成功，开始输出距离值 |
| 3 | 在 0.5m/1.0m/1.5m/2.0m/2.5m/3.0m/3.5m 各采集 500+ 样本 | 距离值基本稳定 |
| 4 | 导出 CSV，用 `sle_accuracy_report.py` 分析 | 输出 Bias/MAE/RMSE 统计 |
| 5 | 对比已有 V3 实验数据 | 确认本硬件 V3 偏差模式与已有数据一致 |

## 阶段三：多基站定位

**目标：** 验证多 Anchor 定位精度和 GTTT 调度稳定性。

**所需硬件：** 5 块板（1 Tag + 4 Anchor）

| 步骤 | 操作 | 预期结果 |
| --- | --- | --- |
| 1 | 4 块板烧录 anchor0-3 固件 | 烧录成功 |
| 2 | 1 块板烧录 tag 固件 | 烧录成功 |
| 3 | 按 Kconfig 默认坐标放置 Anchor | ANC0(0,0,2558) ANC1(4000,0,2665) ANC2(-2310,5040,2686) ANC3(1050,4000,1250) -- 单位 mm |
| 4 | 上电，Tag 自动扫描连接 4 个 Anchor | 串口输出连接状态和定位计算过程 |
| 5 | Tag 在已知坐标点静止，记录定位输出 | 定位精度 ≤ 亚米级 |
| 6 | Tag 移动，记录定位轨迹 | 轨迹连续，无明显跳变 |
| 7 | 关闭 1 个 Anchor 电源，观察 Tag 降级 | 自动切换 2D 模式，定位仍可用 |

## 阶段四：外设功能验证

| 步骤 | 操作 | 预期结果 |
| --- | --- | --- |
| 1 | 触发蜂鸣器（寻找功能） | BUZZER2 正常发声，音量可接受 |
| 2 | 检查蜂鸣器动作时系统电压 | `SLE_3V3` 无明显复位级别压降 |
| 3 | 对接 SDK NFC HAL 后测试 NFC 功能（外接线圈） | NFC TAG 可被手机识别 |
| 4 | 用万用表测量 `VBAT` 和 `BAT_ADC` | 分压比约 3:1，ADC 电压 < 1.5V |
| 5 | 增加并启用调试 LED 驱动 | GPIO_03/04/05 分别反映启动、SLE 和加速度状态 |
| 6 | 读取 LIS2DW12 `WHO_AM_I` 并触发运动事件 | I2C 读写正常，运动事件可被软件识别 |

## 阶段五：低功耗与续航验证

**目标：** 评估系统休眠功耗和 CR2032 续航能力。

**所需硬件：** 1 块板卡 + 万用表（uA 档）或专用功耗分析仪

| 步骤 | 操作 | 预期结果 |
| --- | --- | --- |
| 1 | 对接 LiteOS/PMU 深睡 API 后，使系统进入深度休眠并测量整机电流 | 休眠电流 < 10uA（参考星闪低功耗设计目标） |
| 2 | 系统进入浅度休眠（周期广播）后测量平均电流 | 平均电流 < 50uA |
| 3 | 使用已确认无 SWD 冲突的唤醒源触发唤醒，测量唤醒延迟 | 从中断到 SLE 就绪 < 100ms |
| 4 | 使用 CR2032 标称容量（约 225mAh）估算续航 | 休眠续航 > 6 个月，周期广播续航 > 1 个月 |
| 5 | 蜂鸣器连续动作时测量系统电压 | VBAT 压降不超过 0.3V，系统不复位 |
