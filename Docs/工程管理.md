# 工程管理

## 1. 工程边界

当前工作区由三个独立 Git 仓库和一个 SDK 参考 gitlink 构成：

| 仓库/目录 | 职责 | 提交内容 | 不应提交 |
| --- | --- | --- | --- |
| 根仓库 | 项目管理、硬件和项目级文档 | `Docs/*.md`、硬件插图、`CHANGELOG.md`、管理脚本 | 嵌套仓库源码、编辑器配置、构建缓存 |
| `sle_local/` | BS21E 固件与实验 | 应用源码、Kconfig、构建工具、必要实验数据 | `.venv`、`.uv-cache`、`src/output`、临时日志 |
| `hisiflash/` | 烧录工具 | Rust 源码、测试和工具文档 | `target/` |
| `Docs/fbb_bs2x/` | SDK 参考快照 | 固定上游版本 | 项目功能改动 |

`Docs/fbb_bs2x/` 在根仓库索引中是 gitlink，但当前缺少 `.gitmodules` 映射。该状态不影响本机阅读，但会导致新环境执行 `git submodule` 失败。确认上游仓库地址后，应补齐 `.gitmodules` 或改为明确的普通参考目录。

## 2. 权威信息源

| 信息 | 权威源 |
| --- | --- |
| 原理图网络、器件和 DRC | 嘉立创 EDA MCP 实时读取 |
| BS21 电气与布局要求 | `BS2XV100 硬件指南_02.pdf` |
| 固件行为和 GPIO/Kconfig | `sle_local/src/` 实际源码 |
| 构建命令 | `sle_local/src/build.py`、`sle_local/pyproject.toml`、`uv.lock` |
| 烧录参数 | 本地 `hisiflash --help` 和 `hisiflash/README.md` |
| 测试结果 | 带 BUILD_META、环境说明和原始日志的测试记录 |

文档用于解释和索引，不应覆盖与权威源冲突的事实。

## 3. 分支与提交

- 每个仓库独立检查 `git status`、创建提交和推送。
- 一个提交只处理一个明确主题，例如“更新 LED 选型”或“修复 Tag ADC 引脚”。
- 修改硬件、固件接口或测试标准时，在同一工作项中同步相关文档。
- 根仓库 `CHANGELOG.md` 记录跨子系统、影响交付的变化；子仓库变更记录保留在各自仓库。
- 禁止从根仓库批量添加 `sle_local/` 或 `hisiflash/`。

## 4. 构建与产物

### 固件

```bash
cd sle_local
UV_CACHE_DIR=.uv-cache uv sync
UV_CACHE_DIR=.uv-cache CCACHE_DIR=.ccache \
  uv run --directory src python build.py -ninja standard-bs21e-1100e
```

- 临时构建产物：`sle_local/src/output/`，不提交。
- 角色固件归档：`sle_local/output/firmware/locate/<role>/`，仅在明确需要交付时保留。
- 批量构建必须通过 `uv run python tools/build_locate_firmwares.py ...` 执行。

### hisiflash

```bash
cd hisiflash
cargo build --release
```

- 临时产物：`hisiflash/target/`，不提交。
- 使用本地源码版本时，命令固定为 `./hisiflash/target/release/hisiflash`，避免与系统安装版本混淆。

## 5. 硬件变更流程

1. 使用 MCP 读取当前原理图页或全工程网表。
2. 对 BS21 关键电路同时核对硬件指南。
3. 修改器件/网络后重新读取语义网表并执行 DRC。
4. 同步 `硬件设计.md`、BOM 风险、测试方案和焊接说明。
5. 切到 PCB 画布后复核 PCB DRC、RF、天线、NFC、去耦和 DCC 回路。

当前基线：`BS21_1/Board1/P1/PCB1`；原理图 DRC 尚有 25 个警告；PCB 尚未完成 MCP 复核。

## 6. 测试与发布门禁

| 阶段 | 最低门禁 |
| --- | --- |
| 原理图冻结 | DRC 警告逐项确认；关键器件有可采购料号；NFC/蜂鸣器实际封装明确 |
| PCB 打样 | PCB DRC 通过；RF/天线净空、DCC 回路、晶振和测试点人工复核 |
| 固件交付 | 可重复构建；记录 Git commit、Kconfig、目标平台和 BUILD_META |
| 板级测试 | 记录 VBAT/SLE_3V3/DEC4、串口日志、固件版本和异常 |
| 定位测试 | 保存原始 CSV、环境、Anchor 坐标、固件角色和分析报告 |

## 9. 日常检查

从项目根目录执行：

```bash
./scripts/project-status.sh
```

该脚本只读取状态，不修改仓库，用于快速发现三个仓库的未提交修改、固件产物和磁盘占用。
